# C.I. #02 — Agent Economic Action Gate

**Status:** LIVE · Apify · RapidAPI

## Canonical Question

> Is it economically rational for this agent to buy or execute this capability/action?

A deterministic economic gate for autonomous agents deciding whether a paid action creates enough marginal value versus doing nothing or using a substitute.

## Machine Contract

**Inputs:** task value, currency, baseline success probability, confidence, proposed action cost and expected success delta, plus optional substitutes.

**Decision outputs:**

- `BUY`
- `SKIP`
- `STOP`
- `ESCALATE`

Additional outputs include break-even price ceiling, expected value, marginal value, structured reasoning, and substitute comparison.

## Core Rule

```text
EV = probability × task_value - incremental_cost
```

The capability uses deterministic decimal arithmetic and does not require LLM inference for the economic decision.

## Example

```json
{
  "task_value": 100,
  "currency": "USD",
  "baseline_success_probability": 0.5,
  "confidence": 0.95,
  "action": {
    "id": "paid-verifier",
    "cost": 3,
    "success_probability_delta": 0.15
  },
  "alternatives": [{
    "id": "other-verifier",
    "cost": 2,
    "success_probability": 0.6,
    "confidence": 0.9
  }]
}
```

For this example, the modeled decision is **BUY**, with a break-even price ceiling of **USD 7**.

## Boundaries

This is not a wallet, procurement platform, generic budget guard, pricing optimizer, or tool-discovery system. It evaluates one modeled economic action against baseline and mutually exclusive substitutes. It never moves money or executes the action.

## Direct API Access (x402)

- **Endpoint:** [https://ci-002-production.up.railway.app/x402/v1/evaluate](https://ci-002-production.up.railway.app/x402/v1/evaluate)
- **Method:** `POST`
- **Content type:** `application/json`
- **Price:** `0.001 USDC` per evaluation
- **Network:** Base mainnet (`eip155:8453`)

Preview the payment challenge without paying:

```bash
curl -i 'https://ci-002-production.up.railway.app/x402/v1/evaluate' \
  -H 'Content-Type: application/json' \
  --data '{"task_value":100,"currency":"USD","baseline_success_probability":0.5,"confidence":0.95,"action":{"id":"paid-verifier","cost":3,"success_probability_delta":0.15}}'
```

Expected response: `402 Payment Required`, with an x402 v2 `PAYMENT-REQUIRED` header containing the price, network, asset, recipient and Bazaar metadata. This command makes no payment and returns no economic evaluation.

To obtain the evaluation, use an x402-compatible client with USDC on Base: read the challenge, authorize the specified payment, and retry the same POST with the `PAYMENT-SIGNATURE` header. Invalid input is rejected before payment processing. The provider's Coinbase API keys are not required by buyers.

The `currency` field describes the units of the modeled task value and action cost; it does not change the API's USDC payment asset. Opening the endpoint in a browser sends GET and is not a supported evaluation request.

This endpoint is available directly to x402-compatible clients; marketplace discovery is not required to call it.
