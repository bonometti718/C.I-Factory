# C.I. #02 — Agent Economic Action Gate

**Should an AI agent pay for a tool call, verification step, or other action?**

[Run on Apify](https://apify.com/bono718/agent-economic-action-gate) · [Use RapidAPI](https://rapidapi.com/bono71822/api/agent-economic-action-gate3) · [Direct API access (x402)](#direct-api-access-x402) · [Capability portfolio](../README.md)

## The problem it solves

An autonomous agent can buy an action that improves its chance of completing a task. But is that improvement worth the price, compared with its baseline and available substitutes?

Agent Economic Action Gate evaluates one proposed action using caller-supplied task value, success probabilities, costs, and confidence. It returns a deterministic economic decision and a maximum rational price. Use it before a paid API call, external verification step, or capability purchase in an agent workflow.

Relevant integration areas include AI agent cost control, tool-call economics, expected-value decision making, and paid capability selection. The gate evaluates the supplied model; it does not discover tools, estimate probabilities, execute actions, or move money.

## Quickstart

1. Choose [Apify](https://apify.com/bono718/agent-economic-action-gate) or [RapidAPI](https://rapidapi.com/bono71822/api/agent-economic-action-gate3), and review the current plan and run budget.
2. Paste the complete JSON below into the Actor input or RapidAPI request body.

4. Let your orchestration policy decide whether to execute the action. The gate itself does not purchase it.

For direct payment per evaluation, use the [x402 endpoint](#direct-api-access-x402) with an x402-compatible client.

## Complete input example

Save as `input.json` for the API examples. The task is worth USD 100; the proposed verifier costs USD 3 and increases modeled success probability from 0.50 to 0.65. A substitute costs USD 2 with a success probability of 0.60.

```json
{
  "task_value": 100,
  "currency": "USD",
  "baseline_success_probability": 0.5,
  "confidence": 0.95,
  "action": {
    "id": "paid-verifier",
    "cost": 3,
    "success_probability_delta": 0.15
  },
  "alternatives": [{
    "id": "other-verifier",
    "cost": 2,
    "success_probability": 0.6,
    "confidence": 0.9
  }]
}
```

## Verified example result

The RapidAPI gateway integration was tested on October 5, 2026 with this example. It returned HTTP `200 OK` with these fields:

| Field | Value |
|---|---|
| `decision` | `BUY` |
| `max_rational_price` | `7` |
| `expected_value` | `62` |
| `advantage_over_best_outside` | `4` |

At the supplied probabilities and costs, the proposed action has modeled expected value 62, versus 58 for the substitute and 50 for the baseline. The USD 7 ceiling is where its modeled advantage over the best outside option reaches break-even. These results depend on the supplied estimates; they are not a prediction of actual task success.

## Machine contract

**Inputs:** task value, currency, baseline success probability, confidence, proposed action cost and expected success delta, plus optional mutually exclusive substitutes.

**Decision outputs:** `BUY`, `SKIP`, `STOP`, or `ESCALATE`. Additional outputs include a break-even price ceiling, expected value, marginal value, structured reasoning, and substitute comparison.

```text
EV = probability × task_value - incremental_cost
```

The economic decision uses deterministic decimal arithmetic and requires no LLM inference. The `currency` field specifies the units of the modeled task value and action costs, not the payment asset used to access the API.

- **Endpoint:** [https://ci-002-production.up.railway.app/x402/v1/evaluate](https://ci-002-production.up.railway.app/x402/v1/evaluate)
- **Method:** `POST`
- **Content type:** `application/json`
- **Price:** 0.001 USDC per evaluation
- **Network:** Base mainnet (`eip155:8453`)

Preview the payment challenge without paying, using the same `input.json`:

```sh
curl -i \
  --request POST \
  --url "https://ci-002-production.up.railway.app/x402/v1/evaluate" \
  --header "Content-Type: application/json" \
  --data-binary @input.json
```

Expected response: `402 Payment Required`, with an x402 v2 `PAYMENT-REQUIRED` header containing the price, network, asset, recipient, and Bazaar metadata. This command makes no payment and returns no economic evaluation.

To obtain the evaluation, use an x402-compatible client with USDC on Base: read the challenge, authorize the specified payment, and retry the same POST with the `PAYMENT-SIGNATURE` header. Invalid input is rejected before payment processing. Provider Coinbase API keys are not required by buyers. Opening the endpoint in a browser sends GET and is not a supported evaluation request. Direct access does not require marketplace discovery.

## Operational boundaries

This capability evaluates one modeled action against its baseline and mutually exclusive substitutes. It is not a wallet, procurement platform, generic budget guard, pricing optimizer, or tool-discovery system. It never executes the action or moves money. The quality of the decision depends on the caller-supplied task value, probabilities, costs, and confidence.
